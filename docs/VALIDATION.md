## Embedded native application checks

The macOS bundle opened its own SQLCipher vault in the application data directory using a random key stored in macOS Keychain. It used the in-process request bridge, with no local HTTP listener and no collector configured. A synthetic preference survived process termination and restart. The guided flow discovered the real local Ollama installation, sent an explicit synthetic prompt to qwen3:0.6b, received a response, and recorded 22 input / 201 output tokens reported by that provider. No memory grant was created. A History JSON export was saved through the native command under Documents/OMNI; the interface lock and local reopen control were exercised. This is a development macOS build, not a notarized release.

New core tests cover embedded initialization, random session credentials, direct authenticated request routing, method/path and body limits, independent owner/agent authorization, encrypted persistence, exclusive vault access, analytics refusal without a collector, and an explicitly enabled ephemeral loopback listener. Key adapter tests cover missing/corrupt credentials without silent replacement, random key creation with verified persistence, and bounded JSON/CSV export names, formats and destinations. They do not certify a platform secure store on an untested OS.

Mobile browser layout checks cover 390×844 portrait, 390×420 with reduced visible height, 844×390 landscape and simulated safe-area insets. Controls remained reachable without horizontal overflow. These are browser layout checks, not physical-device tests. Android and iOS have native key adapters and packaging jobs; their exact build and execution results must be read separately from browser evidence.

The history regression exposed an initial search debounce resetting pagination even without a query change. The effect now waits only when the normalized query differs from the applied search. All four existing browser suites passed after that correction.

The fifth suite, `test:native`, exercises iOS and Android interface branches with a test-only Tauri invoke bridge backed by an isolated real Rust core and SQLCipher vault. It covers session provisioning, IPC-only API calls, local memory CRUD, synthetic model inference, model and history views, native metadata export payloads, mobile setup, and lock persistence across reload. Direct browser API requests are rejected in the test. This does not test the production Swift/Kotlin bridge or device secure stores.

## Android execution evidence

A universal development APK containing ARM64 and x86_64 native libraries was compiled and installed on a dedicated Android 15 AOSP ARM64 emulator. The actual application Activity and native plugin started, created the encrypted vault through Android Keystore, and reopened after force-stop. The database header was checked without printing its contents: it is not a plaintext SQLite header. Five instrumented tests ran against Android Keystore with zero failures or skips: persistent key recovery, non-exportable wrapping key, missing-key refusal, corrupted-envelope refusal and authenticated ciphertext modification rejection. These are emulator results, not physical-device, Play Store or system-wide VPN certification.

The local universal Android evaluation APK is 102,007,285 bytes and includes both ARM64 and x86_64. Native development builds omit Rust DWARF symbols to keep the installable package smaller; debug signing and runtime checks remain enabled.

The reusable Android smoke script also passed against a fresh installation of the final APK: native boot created the encrypted database, force-stop preserved it, and reopening produced a new encrypted audit write with the original database salt. It does not inspect plaintext or report any encryption key. The platform workflow repeats this check on a disposable x86_64 AOSP emulator before running the five Keystore tests.

A later macOS app/DMG evaluation package was built successfully without distribution signing. Opening that new binary against the existing test vault requested macOS Keychain authorization; the computer-control tool refused access to the protected SecurityAgent UI. That attempt was cancelled without changing the vault or its key. The earlier native application flow remains the measured end-to-end macOS evidence; a build alone does not imply authorization to reopen an existing user's keychain item.
