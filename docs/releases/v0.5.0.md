# OMNI 0.5.0 — Observable startup and safe recovery

## Status

macOS reliability candidate. The desktop shell and interface are version 0.5.0; the unchanged core and device-security crates retain version 0.4.0. Packaging, source validation and native acceptance are separate gates. This document does not declare the reported Mac repaired.

## What changes

- A small independent bootstrap keeps a styled recovery screen available when application imports fail. Reload retries a transient asset failure.
- Opening the native vault has a 20-second interface deadline. A blocked or rejected request presents a retry screen without deleting data or replacing a key. Timing out the interface does not cancel or duplicate the native vault initialization.
- A macOS native alert appears after 35 seconds without an interface acknowledgement, including when WebKit never renders HTML. Reload and Quit remain available independently of JavaScript.
- Packaging smoke tests now require a signal from the launched frontend after mounting and successfully reading core state. A process, window or encrypted database alone cannot pass. Entering recovery fails the smoke check.
- Production-bundle fault tests cover the missing entry script, failed application import, successful reload, rejected vault and stalled vault. Native build coverage adds macOS 26 alongside macOS 15.

The readiness signal contains only a fixed event and application version. It is a test signal, not cryptographic attestation or a screenshot. No user content, key, token or filesystem path is included.

## Investigation on the affected Mac

On macOS 26.5.2 (25F84), Apple Silicon, the installed 0.4.0 package reproduced a blank native window before vault provisioning. The preserved 0.2.0 package also exhibited the failure in this session. A standalone Swift WKWebView displaying a static local HTML string, without OMNI code, vault access or network requests, reproduced the same blank content.

Isolating only the OMNI WebKit/cache directories did not resolve it; the original directories were restored. A private local encrypted-vault backup was preserved without exporting its key. No vault reset, Keychain deletion, Gatekeeper/SIP change or privacy-setting change was made. Restarting the WebPrivacy service did not restore rendering. The underlying system cause remains unconfirmed; these observations do not prove a 0.3-specific code regression.

The 0.5.0 debug application's native recovery dialog and Reload action were visibly checked while this failure was present. A full native conversation and an existing-vault upgrade on the affected Mac still require a functioning system renderer. Restart macOS and repeat acceptance before marking that machine supported. A restart is a diagnostic next step, not a verified fix.

## Roadmap scope

This begins G1 release reliability: bounded startup, visible recovery and a stricter release gate. G1 still requires trusted signing/notarization, real client/provider workflows, supported-device update and restore evidence, and independent review. No SDK, new interception protocol, commercial-provider certification or measured carbon saving is introduced.

See [delivery status](../DELIVERY.md), [validation](../VALIDATION.md) and [the roadmap](../../ROADMAP.md). Existing 0.4.0 Android delivery remains the last accepted Android package until exact 0.5.0 native and update records exist.
