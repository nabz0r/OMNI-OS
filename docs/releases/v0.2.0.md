# OMNI 0.2.0 · Your rules. Every request.

This MVP evaluation release brings request policies and text attachments to the native macOS and Android applications. Your memory determines the context a model may receive. Policies determine whether a request may leave at all.

## Changes

- **Policies console:** configure allowed text-file types, file and request limits, blocking expressions and required expressions. Test a saved policy locally before sending anything.
- **Enforcement before disclosure:** launcher messages, compatible gateway requests, conversation history, tools and injected context pass through the policy engine. Rejected requests do not reach the provider.
- **Text attachments:** attach supported UTF-8 text files to a conversation. The engine checks names, media types, contents and limits. Binary and opaque uploads are rejected.
- **Decision history:** inspect the outcome and policy revision without storing the prompt, file names or matching text in the decision trail.
- **Organization baseline:** a deployment can supply a read-only baseline through `OMNI_MANAGED_POLICY_FILE`; local rules cannot relax it. Fleet distribution, administrator enrollment and mobile managed configuration are not included.
- **Release provenance:** both installer records identify their version, exact source revision and package hashes. Android acceptance now covers native policy editing, invalid expressions, file filtering, blocked outbound requests and persistence.

## Install or update

Use the macOS Apple Silicon DMG on macOS 14.4 or later, or the Android APK on ARM64/x86_64 devices with API 24 or later and a current System WebView. No OMNI server or development tools are required. Connect your own model endpoint or provider account.

Quit OMNI before replacing the Mac application. On Android, install the APK as an update over the previous evaluation build signed with the same identity. Keep the vault and its platform credential. **Do not uninstall a personal Android vault to resolve a signing mismatch.** Independent CI debug APKs can have different signing identities.

## Distribution boundary

This is a **pre-release for evaluation**. macOS has an ad-hoc resource seal, without Developer ID signing or notarization. Android uses the existing development signing identity, without Play Store distribution. There is no bundled inference model, automatic cross-device synchronization, complete recovery wizard or system-wide mobile VPN. Local owners can edit local policy; this is not an OS-enforced enterprise administrator boundary.

The delivery record and acceptance evidence identify the actual tested packages. Emulator tests do not establish compatibility with every physical phone or supported Android version. See [Policies](../POLICIES.md), [delivery instructions](../DELIVERY.md), and [platform validation](../VALIDATION.md).
