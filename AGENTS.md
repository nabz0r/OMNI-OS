# Repository language policy

All deliverables in this repository must be written in clear, natural English for an international audience. This includes documentation, README files, diagrams and their labels, interface copy, error messages, code comments, examples, and new filenames.

Discuss work with the project owner in French unless they request another language. Conversation language does not change the English requirement for deliverables.

When translating or editing:

- Preserve technical meaning, numerical values, security limitations, and the distinction between implemented features and target architecture.
- Keep API identifiers, configuration keys, protocols, URLs, and third-party names intact. Update links and anchors when renaming documents or headings.
- Preserve multilingual input support and intentional non-English language data, such as classifier keywords or language-specific test cases. These are functional data, not untranslated interface copy.
- Keep historical design notes explicitly identified as historical; do not present their proposals as implemented behavior.
- Check Markdown links and render changed Mermaid diagrams before publishing documentation changes.
